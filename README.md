# kodpauza

Рекламная платформа для инструментов разработки. В проект входят кабинеты трех ролей, глобальные кампании, серверная выдача рекламы, подписанные события, финансовый учет, пополнение через ЮKassa и безопасные lifecycle-интеграции Codex и Claude Code.

Продуктовые формулы, лимиты и основания списания зафиксированы в
[условиях показа и оплаты](docs/ad-delivery-policy.md).

## Запустить текущий проект

База и зависимости уже подготовлены. Для следующего запуска достаточно:

```bash
cd /Users/mitfleg/Desktop/projects/ads_ext
docker compose up -d
docker compose ps
```

Откройте `http://localhost:3000`. API и проверки состояния доступны на `http://localhost:4000`, `http://localhost:4000/health` и `http://localhost:4000/ready`.

Локальные аккаунты:

- администратор: `admin@kodpauza.local` / `admin123456`;
- разработчик: `dev@kodpauza.local` / `dev123456`;
- рекламодатель: `adv@kodpauza.local` / `adv123456`.

Остановить проект без удаления данных:

```bash
docker compose down
```

Не добавляйте `-v`, если хотите сохранить локальную PostgreSQL-базу.

## Локальная разработка с hot reload

Для разработки не запускайте API и web в production-контейнерах. Оставьте в Docker только PostgreSQL, а приложения запускайте локально из двух терминалов:

```bash
# Терминал 1: поднимет PostgreSQL, применит миграции и запустит API
make api

# Терминал 2: запустит Next.js
make web
```

Либо запустите оба приложения одной командой:

```bash
make dev
```

`make api`, `make web` и `make dev` загружают корневой `.env`. Изменения TypeScript/React применяются автоматически без пересборки Docker-образов. Локальная CAPTCHA не загружается; сервер принимает только настроенный dev-токен при включенном `KODPAUZA_LOCAL_DEVELOPMENT=true`.

Блоклист временных почтовых доменов хранится локально и объединяется из двух GitHub-источников. Обновить его можно командой `make email-domains`; API не обращается к внешним сервисам при каждой регистрации.

## CI/CD и production

GitHub Actions проверяет код и Dockerfile, публикует готовые API/web-образы в GHCR и при включённом production deploy обновляет сервер по неизменяемым image digest. Исходники на production-сервере не собираются. Настройка GitHub, сервера, переменных и отката описана в [deploy/README.md](deploy/README.md).

Все доступные команды:

```bash
make help
```

## Первый запуск из чистой копии

```bash
cp .env.example .env
pnpm install
docker compose up -d postgres
pnpm db:local:reset
docker compose up -d --build api web
docker compose ps
```

Перед запуском замените `JWT_SECRET`, `IP_HASH_SECRET` и `KODPAUZA_EMAIL_VERIFICATION_SECRET` в `.env` тремя независимыми значениями из `openssl rand -hex 32`. Также задайте пару ключей Cloudflare Turnstile (`NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `KODPAUZA_CAPTCHA_SECRET_KEY`) и рабочий SMTP через `KODPAUZA_SMTP_*`. API в production намеренно не стартует без CAPTCHA, TLS-защищенной отправки писем и этих секретов. По умолчанию PostgreSQL публикуется на порту `55432`, чтобы не конфликтовать с уже установленной локальной БД.

`pnpm db:local:reset` удаляет и пересоздает только схему, имя которой заканчивается на `_local`. Схема `public` и другие существующие данные не затрагиваются. Не используйте `prisma migrate reset` для общей базы.

Production-подобный Docker-стек после изменения кода пересобирается командой:

```bash
docker compose up -d --build api web
```

## Как работает сценарий

1. Рекламодатель пополняет баланс на произвольную сумму через ЮKassa. Баланс меняется только после серверного подтверждения платежа.
2. Рекламодатель создает HTTPS-объявление. Кампания получает статус `pending`.
3. Администратор проверяет текст, ссылку, CPM и бюджет, затем одобряет или отклоняет кампанию с причиной.
4. Расширение, авторизованное как разработчик, запрашивает объявление. API создает одноразовую выдачу с ограниченным сроком.
5. После пяти непрерывных секунд подтвержденной DOM-видимости расширение отправляет HMAC-подписанный показ. Скрытие или сворачивание блока сбрасывает таймер; повторная отправка того же события не списывает деньги второй раз.
6. За чистый показ рекламодатель платит полную стоимость, разработчику начисляется 50%, разница учитывается как маржа платформы. Подозрительные показы и клики не оплачиваются.
7. Разработчик создает заявку на вывод. Сумма атомарно уходит в резерв и не может быть запрошена второй раз.
8. Администратор выполняет перевод во внешнем сервисе и подтверждает его уникальным номером либо отклоняет заявку с полным возвратом резерва.
9. Администратор видит кампании, пополнения, выплаты, пользователей, финансы, события, сигналы накрутки и журнал решений.

Прием оплаты реализован через ЮKassa и включается серверными ключами магазина. Локальный seed использует тестовые балансы. Для разработчиков реализованы заявки, резерв и ручное подтверждение перевода; автоматической отправки денег провайдером нет. Настройка платежей: [docs/yookassa.md](docs/yookassa.md), процесс выплат: [docs/developer-payouts.md](docs/developer-payouts.md).

## Расширение VS Code

Для локальной пересборки и установки в Cursor выполните:

```bash
pnpm extension:local
```

Команда собирает `packages/vscode-extension/dist/kodpauza.vsix`, устанавливает его поверх текущей версии и автоматически указывает локальные адреса API и кабинета в пользовательских настройках Cursor. Перед первым изменением рядом с `settings.json` создается резервная копия `settings.json.kodpauza-backup`.

Настройки и авторизация сохраняются при последующих переустановках. После команды выполните `Developer: Reload Window` во всех открытых окнах Cursor, затем:

1. `Kodpauza: Войти` под `dev@kodpauza.local`.
2. `Kodpauza: Войти` — совместимые интеграции подключатся автоматически.
3. Перезапустить окно редактора и отправить запрос в Codex или Claude Code.

Если Codex сообщит, что hooks не доверены, запустите `codex` в терминале и выполните `/hooks` в Codex CLI. В боковой панели Codex внутри редактора эта slash-команда не работает.

Интеграция добавляет собственные записи в `~/.codex/hooks.json` и `~/.claude/settings.json`, затем устанавливает UI-патчи только для явно проверенных версий Codex и Claude Code. Перед изменением создаются полные резервные копии, а несовпадение версии, структуры или SHA-256 останавливает установку. Hook-процесс отбрасывает входной поток без разбора и передает локальному bridge только событие начала/окончания и рабочую папку для выбора нужного окна. Полный транспорт описан в [docs/privacy.md](docs/privacy.md).
