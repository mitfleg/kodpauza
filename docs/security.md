# Безопасность

Документ фиксирует фактическую защиту технического MVP и оставшиеся требования публичного запуска.

## Реализовано

- bcrypt с ограничением пароля в 72 байта и настраиваемой стоимостью хеширования;
- серверная CAPTCHA регистрации, встроенный и настраиваемый запрет одноразовых email-доменов и подтверждение почты шестизначным кодом, который хранится только как HMAC-хеш;
- код ограничен сроком, числом попыток и cooldown повторной отправки; неподтвержденный аккаунт не получает JWT/event secret и блокируется в вебе, API и расширении;
- JWT только `HS256`, issuer/audience и срок по умолчанию 12 часов;
- отдельные проверки ролей для разработчика, рекламодателя и администратора;
- строгая Zod-валидация тела, query и числовых границ;
- запрет HTTP-ссылок в кампаниях и минимального CPM ниже 20 рублей;
- одноразовая серверная выдача рекламы, HMAC события, окно времени и идемпотентность;
- транзакционное списание/начисление, блокировка конкурентных событий и ограничения БД;
- подозрительные события не оплачиваются;
- IP и User-Agent хешируются, сырые значения не сохраняются и хэши не отдаются веб-клиенту;
- CORS allowlist, security headers, `no-store`, нормализованный IP rate limit;
- редактирование активной кампании возвращает ее на модерацию;
- запрет публичной регистрации администратора и отключения подписей в production;
- production не стартует с короткими/default secrets, пустым CORS или неразрешенным HTTP;
- аудит одобрения, остановки и отклонения кампаний.
- серверная интеграция ЮKassa: двойная идемпотентность, повторная проверка webhook через API провайдера, сверка суммы/валюты/metadata и транзакционное зачисление;
- уникальная связь платежа с ledger-записью, исключающая повторное пополнение;
- платежные данные банковских карт не проходят через API или веб Kodpauza.
- заявки разработчиков резервируют баланс serializable-транзакцией; один открытый запрос и уникальный номер внешнего перевода защищены ограничениями БД;
- заявка на выплату хранит только ФИО получателя, российский телефон СБП и название банка; номер карты, CVC, PIN, банковский пароль и коды из SMS не принимаются.

## Секреты и окружение

Обязательны `DATABASE_URL`, `JWT_SECRET`, `IP_HASH_SECRET`, `KODPAUZA_EMAIL_VERIFICATION_SECRET`, `KODPAUZA_ALLOWED_ORIGINS`. Для production также нужны ключ CAPTCHA и SMTP с TLS. Генерируйте секреты как минимум из 32 случайных байт и храните их в secret manager, а не в образе или репозитории.

Для регистрации задаются клиентский `NEXT_PUBLIC_SMARTCAPTCHA_SITE_KEY` и серверный `KODPAUZA_CAPTCHA_SECRET_KEY`. CAPTCHA всегда проверяется API через Yandex SmartCaptcha; в production обязателен `KODPAUZA_CAPTCHA_EXPECTED_HOSTS=kodpauza.ru`. Письма отправляются через `KODPAUZA_EMAIL_TRANSPORT=smtp` и `KODPAUZA_SMTP_*`; production не запускается без CAPTCHA с проверкой домена и SMTP с TLS. `console` и dev-токен допустимы только в development/test.

Новые временные почтовые домены можно оперативно добавлять через `KODPAUZA_DISPOSABLE_EMAIL_DOMAINS` без изменения кода.

Для приема платежей вместе задаются `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`. При отсутствии обоих API продолжает работать, но пополнение отключено. Код НДС `YOOKASSA_RECEIPT_VAT_CODE` включается только после настройки кассы и юридической проверки чекового сценария. Полная инструкция: [yookassa.md](yookassa.md).

`KODPAUZA_ALLOW_INSECURE_LOCALHOST=true` допустим только для локального Docker. На сервере нужны HTTPS URL кабинета/API и корректный `KODPAUZA_TRUST_PROXY` за доверенным reverse proxy.

Автоматическое пополнение новых рекламодателей отключено. Переменная `KODPAUZA_TEST_ADVERTISER_CREDIT_KOPECKS` работает только при `NODE_ENV=test`.

## Осталось до публичного production

- перевести браузерную сессию с `localStorage` на HttpOnly Secure SameSite cookie или равноценную BFF-схему;
- вынести rate limits в общий Redis/совместимый store перед запуском нескольких API-инстансов;
- добавить управляемый lifecycle администраторов, блокировку учетных записей и восстановление доступа;
- добавить аудит входов и решений по fraud-флагам;
- настроить централизованные логи, метрики, alerting, резервные копии и проверку восстановления;
- определить retention и очистку просроченных `AdServe`, событий и логов;
- провести внешний security review и нагрузочное тестирование.
- реализовать возвраты с обработкой `refund.succeeded` и автоматическим обратным ledger-движением до разрешения самостоятельных возвратов;

## Проверка

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm audit --prod
docker compose config
docker compose up -d --build
curl -fsS http://localhost:4000/health
curl -fsS http://localhost:4000/ready
```

Тесты должны работать только со схемой `_test`; локальный seed/reset - только со схемой `_local`.
