# Чек-лист запуска в России

Это инженерно-продуктовый список, не юридическая консультация.

## Готово для локального пилота

- русские кабинеты разработчика, рекламодателя и администратора;
- регистрация/вход, защита маршрутов и разделение ролей;
- создание, модерация, остановка и повторная отправка кампаний;
- серверная выдача и HMAC-подписанные идемпотентные события;
- транзакционное тестовое списание и начисление 50% разработчику;
- антифрод без оплаты подозрительных событий;
- финансовая сводка, события, fraud-флаги и журнал в админке;
- идемпотентное пополнение через ЮKassa, серверная проверка webhook и история платежей;
- транзакционные заявки на вывод, резерв, ручное подтверждение и административный аудит;
- реальные интеграции Codex и Claude Code и готовый VSIX;
- изолированные `_local`/`_test` схемы, миграции, seed и Docker Compose;
- liveness/readiness, CORS, security headers, rate limits и production guards;
- описание фактического транспорта и запрет сбора кода.
- версионированные публичные документы и отдельные согласия регистрации;
- доказательства согласий в БД, пользовательский экспорт и очередь privacy-заявок;
- необязательное поле `erid`: оно не блокирует создание и модерацию кампании;
- информационный cookie-баннер: Метрика запускается по умолчанию, пользователь может отключить ее на `/cookies`.

## Перед первым production-деплоем этой версии

- заполнить `NEXT_PUBLIC_LEGAL_OPERATOR_NAME`, `STATUS` и `INN` в production variables;
  регистрационный номер, адрес и email заполняются при наличии;
- применить миграцию `20260717120000_legal_acceptances_and_privacy_requests`;
- зарегистрировать тестового пользователя и убедиться, что в `LegalAcceptance` появились три записи;
- проверить автоматический запуск Метрики в новом браузерном профиле, затем отключение и повторное включение на `/cookies`;
- скачать экспорт в разделе «Мои данные», создать заявку и закрыть ее в админке;
- получить письменное заключение юриста по документам и бухгалтера по выплатам/чекам;
- зафиксировать решение по уведомлению Роскомнадзора, локализации базы и внешним обработчикам.

## Обязательно до реальных продаж

- подключить боевой магазин ЮKassa, проверить чеки, реализовать возвраты, ежедневную сверку и бухгалтерский учет;
- утвердить и внедрить процесс реального перевода, KYC/договоры, проверку НПД и получение чеков;
- до открытого оборота рекламы принять отдельное решение по ОРД/ЕРИР и обязательности erid;
- юридически утвердить оферту, политику, согласия, правила споров и возвратов;
- развернуть HTTPS production-домен, secret manager и закрытый PostgreSQL;
- настроить backup/restore, мониторинг, алерты, retention и поддержку;
- перейти на HttpOnly-сессию для веба и shared rate-limit store при масштабировании;
- провести внешний security review и тест нагрузки;
- подготовить публикацию расширения, контакты поддержки и пользовательское согласие.

## Финальная техническая проверка

```bash
pnpm typecheck

pnpm test
pnpm build
pnpm audit --prod
pnpm --filter kodpauza-vscode test
pnpm --filter kodpauza-vscode run package:vsix

docker compose up -d --build
docker compose ps
curl -fsS http://localhost:4000/health
curl -fsS http://localhost:4000/ready
```

После этого вручную пройти регистрацию, рекламодателя, модерацию, разработчика, все вкладки админки, desktop/mobile layout и сценарий расширения.

## Решение go/no-go

- Локальный запуск и закрытый технический пилот без реальных денег: **go**.
- Продажа рекламы и прием реальных денег: **no-go**, пока не пройдена боевая проверка ЮKassa и не закрыты возвраты, ERID/ОРД/ЕРИР, юридические документы и production-эксплуатация.
