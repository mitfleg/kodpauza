# Приватность и транспорт данных

Это техническое описание текущего MVP, а не утвержденная юридическая политика.

## Что фактически передается

При входе пользователь отправляет API email и пароль по настроенному соединению; сервер возвращает JWT, а разработчику также индивидуальный `eventSecret`. Веб-клиент хранит JWT локально в браузере, расширение хранит JWT и `eventSecret` в VS Code `SecretStorage`.

При пополнении рекламного баланса Kodpauza передает ЮKassa сумму, внутренние идентификаторы платежа и рекламодателя, return URL и описание услуги. Если включена отправка чеков, также передается email рекламодателя. Пользователь вводит платежные реквизиты на странице ЮKassa; Kodpauza их не получает.

При запросе объявления расширение передает JWT и `surface`. API связывает случайный `adId` с пользователем, кампанией, ценой, вознаграждением и сроком действия.

Событие показа/клика содержит:

- `eventId`, `adId`, `campaignId`, `surface`;
- `visibleMs` для показа;
- версию расширения, название редактора, имя и версию активного AI-инструмента, а также признак поддержки UI-патча;
- временную метку и HMAC-подпись в заголовках.

Как и любой HTTP-сервер, API получает сетевой IP и User-Agent. Они сразу HMAC-хешируются с `IP_HASH_SECRET`; сырые значения не сохраняются. Хэши используются только внутри антифрода и не возвращаются в кабинеты разработчика или администратора.

Путь workspace используется только локально hook-скриптом, чтобы выбрать правильное окно редактора. Он не включается в рекламные события и не отправляется API. Авторизованное расширение периодически обновляет в `ExtensionInstall` случайный ID установки, версии редактора и Kodpauza, тип ОС и признаки обнаружения/подключения Codex и Claude Code. Пути, код и содержимое чатов в heartbeat не входят.

## Что расширение не читает и не отправляет

- исходный код и текст активного редактора;
- пути и названия файлов или проектов;
- терминал и буфер обмена;
- промпты и ответы ИИ: hook-протоколы Codex и Claude Code подают JSON в stdin, но скрипт Kodpauza только освобождает поток, не разбирает, не сохраняет и не пересылает его;
- содержимое чатов;
- диагностику других расширений на сервер.

Локальная команда диагностики может показать установленные расширения, их версии и пути пользователю, но не передает этот отчет API.

## Локальные интеграции Codex и Claude Code

- `UserPromptSubmit` сообщает о начале ожидания, `Stop` - о завершении;
- hook-скрипт передает `start`/`stop` и локальный `cwd` на случайный loopback-порт `127.0.0.1`;
- каждое окно редактора использует отдельный 256-битный токен; descriptor-файлы имеют права только текущего пользователя;
- локальный bridge принимает тело не больше 2 КБ и не слушает внешние сетевые интерфейсы;
- UI-патч подключается к отдельному фиксированному loopback-порту по случайному 256-битному токену и получает только `active`, `adId` и текст объявления;
- URL объявления не передается в webview: клик уходит локальному bridge, а ссылку открывает расширение Kodpauza;
- перед патчем проверяются версия и SHA-256 файлов Codex или Claude Code, а оригиналы сохраняются в `~/.kodpauza/backups`;
- удаление интеграции удаляет только обработчики Kodpauza, сохраняя остальные hooks пользователя.

## Хранение в БД

- email, bcrypt-хеш пароля, роль, отображаемое имя, статус подтверждения и временный HMAC-хеш кода;
- профиль и внутренние балансы;
- кампании, HTTPS-ссылки, бюджеты и счетчики;
- выдачи рекламы и их срок/факт показа или клика;
- события, клиентские версии, `visibleMs`, IP/User-Agent хэши;
- fraud-флаги, проводки и журнал административных решений.
- идентификатор платежа ЮKassa, сумму, валюту, статус, тестовый признак и даты создания/зачисления.
- заявку разработчика на выплату: сумму, статус, даты, причину решения и номер уже выполненного внешнего перевода.

Номер карты, CVC, банковские токены, телефон СБП, расчетный счет и другие платежные реквизиты Kodpauza не собирает и не хранит.

В закрытой бете участник может добровольно передать имя, банк и телефон СБП во внешнем чате Telegram `@mitfleg`. Эти данные не записываются в БД Kodpauza; содержание чата обрабатывается Telegram по его правилам. Номер карты, CVC, коды из SMS и пароли не запрашиваются.

## До внешнего запуска

- утвердить русскую политику и согласие на телеметрию;
- указать оператора данных, контакты удаления/экспорта и правовое основание;
- назначить сроки хранения и автоматическую очистку;
- определить локализацию и правила трансграничной передачи;
- заменить браузерное хранение JWT на HttpOnly cookie/BFF;
- не добавлять сырые headers, IP, editor context или код в `FraudFlag.metadata` и логи.
