# Пополнение рекламного баланса через ЮKassa

Kodpauza использует серверный Redirect-сценарий ЮKassa. Рекламодатель вводит произвольную сумму от 1 до 10 000 000 рублей, API создает платеж, а браузер переходит на защищенную страницу ЮKassa. Данные карты не проходят через Kodpauza.

## Настройка

Получите в личном кабинете ЮKassa идентификатор магазина и секретный ключ. Передайте их API только через secret manager или переменные окружения:

```env
YOOKASSA_SHOP_ID="<shop-id>"
YOOKASSA_SECRET_KEY="<secret-key>"
YOOKASSA_API_BASE_URL="https://api.yookassa.ru/v3"
YOOKASSA_TIMEOUT_MS="12000"
KODPAUZA_PUBLIC_DASHBOARD_URL="https://kodpauza.ru"
```

Секретный ключ нельзя помещать в `NEXT_PUBLIC_*`, Docker build args, браузерный код или VSIX.

В личном кабинете ЮKassa откройте `Интеграция -> HTTP-уведомления` и добавьте:

```text
https://api.kodpauza.ru/v1/payments/yookassa/webhook
```

Подпишите URL на события `payment.succeeded` и `payment.canceled`. ЮKassa требует HTTPS и порт 443 или 8443.

## Как защищено начисление

1. Браузер генерирует UUID запроса. Повтор с тем же UUID и суммой возвращает существующий платеж.
2. API отдельно генерирует `Idempotence-Key` для ЮKassa и сохраняет его до внешнего запроса.
3. Сумма хранится целым числом копеек. Float для бухгалтерского состояния не используется.
4. Возврат пользователя на сайт не считается подтверждением оплаты.
5. При webhook и ручной проверке API заново запрашивает платеж у ЮKassa по Basic Auth.
6. Сверяются провайдерский ID, сумма, валюта `RUB`, `paid: true` и оба значения `metadata`.
7. Статус платежа, баланс рекламодателя и ledger-запись обновляются одной транзакцией.
8. Уникальный `LedgerEntry.paymentId` и условный переход `pending -> succeeded` блокируют двойное зачисление.

Поддельное уведомление, повторная доставка webhook, измененная сумма или чужой `metadata` не увеличивают баланс.

## Чеки и 54-ФЗ

Нельзя выбирать код НДС наугад. После настройки онлайн-кассы и согласования с бухгалтером задайте:

```env
YOOKASSA_RECEIPT_VAT_CODE="<код ЮKassa от 1 до 12>"
```

Тогда при создании платежа API передает email рекламодателя и позицию `Пополнение рекламного баланса Kodpauza` с признаком предоплаты за услугу. Юридически корректный сценарий зачета аванса и закрывающих чеков зависит от вашей системы налогообложения и настроек кассы; его необходимо утвердить до приема реальных денег.

## Тестовый магазин

Используйте отдельные тестовые `shopId` и `secretKey`. В истории платежа и админке Kodpauza сохраняется `providerTest`. Перед переключением на боевой магазин проверьте:

- успешную оплату и возврат на `https://kodpauza.ru/advertiser`;
- доставку `payment.succeeded` и `payment.canceled`;
- повтор одного webhook без второго начисления;
- отмененный и просроченный платеж без изменения баланса;
- формирование чека, если оно включено;
- сверку суммы в ЮKassa, `AdvertiserPayment` и `LedgerEntry`.

## Эксплуатационные ограничения

- Не меняйте и не удаляйте платежные записи вручную.
- Не делайте возврат только из кабинета ЮKassa: текущий релиз не уменьшает рекламный баланс автоматически после `refund.succeeded`. До реализации возвратного контура возвраты должны сопровождаться ручной блокировкой расходования и корректирующей ledger-операцией администратора.
- Настройте alerting на `failureCode=integrity_mismatch` и ответы webhook 5xx.
- Регулярно сверяйте успешные платежи с реестром ЮKassa.
- При временной ошибке ЮKassa оставляет платеж `pending`; повтор использует прежний ключ идемпотентности.

## API

- `POST /v1/advertiser/payments` — создать платеж;
- `GET /v1/advertiser/payments` — последние 20 платежей и доступность провайдера;
- `POST /v1/advertiser/payments/:id/refresh` — получить актуальный статус у ЮKassa;
- `POST /v1/payments/yookassa/webhook` — входящие уведомления;
- `GET /v1/admin/payments` — последние 100 платежей для администратора.

Официальные материалы: [быстрый старт ЮKassa](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start), [входящие уведомления](https://yookassa.ru/developers/using-api/webhooks), [чеки по 54-ФЗ](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/basics).
