# Антинакрутка

MVP использует простые серверные правила без отпечатков устройства и без чтения лишних данных.

## Правила показов

- `eventId` уникален.
- `visibleMs` должен быть не меньше `5000`.
- Клиент считает только непрерывную видимость; паузы не суммируются.
- Из нескольких открытых окон VS Code/Cursor оплачиваемый таймер работает только в окне с фокусом; потеря фокуса очищает DOM-подтверждение и сбрасывает незавершенный интервал.
- Получение объявления через `/current` не считается видимостью.
- Локальный bridge принимает heartbeat только для текущего `adId` и отдельного валидного `viewId`.
- Скрытые, свернутые, прозрачные, перекрытые и находящиеся вне viewport DOM-элементы не отправляют подтверждение показа.
- Максимум `60` чистых оплачиваемых показов в час на пользователя.
- Максимум `300`, `450` или `600` чистых оплачиваемых показов за скользящие 24 часа в зависимости от уровня аккаунта.
- Исчерпание часовой или суточной квоты не является фродом: API прекращает новые выдачи, не создает `AdEvent` и `FraudFlag` для уже выданного конкурентного показа и ничего не списывает.
- Повтор события в течение 10 секунд помечается `suspicious`.
- `visibleMs > 60000` помечается `suspicious`.
- Проверка владельца IP и начисление выполняются под общей PostgreSQL advisory-блокировкой, поэтому два аккаунта не могут одновременно выиграть гонку.
- Одинаковый нормализованный email нельзя зарегистрировать дважды; параллельные показы одного аккаунта сериализуются отдельной блокировкой пользователя.
- Неизвестный `surface` отклоняется Zod-схемой.
- События без JWT отклоняются.

## Правила кликов

- `eventId` уникален.
- Денег за клик в MVP не начисляется.
- Более `30` кликов в час на пользователя помечаются `suspicious`.

## Начисления

Формула:

```text
rewardKopecks = floor(cpmKopecks / 1000 * 0.5)
```

Для CPM `30000` копеек разработчик получает `15` копеек за чистый показ.

Чистый показ в одной транзакции:

- создает `AdEvent`;
- создает `LedgerEntry`;
- увеличивает `DeveloperProfile.balanceKopecks`;
- увеличивает `DeveloperProfile.totalImpressions`;
- увеличивает `Campaign.spentKopecks`;
- увеличивает `Campaign.impressionsServed`.

Подозрительный показ записывается и создает `FraudFlag`, но не начисляет баланс и не списывает оплату у рекламодателя.

## Минимизация данных

IP и User-Agent хешируются HMAC на сервере. Исходные значения не сохраняются.
