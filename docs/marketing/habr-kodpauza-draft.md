# Как показать рекламу во время работы Codex и Claude Code и не читать код пользователя

AI-агенты в редакторе изменили ритм разработки. Разработчик формулирует задачу,
а затем ждёт, пока агент изучает проект, запускает команды, меняет файлы и
готовит ответ. Иногда это несколько секунд, иногда — заметно дольше.

Мы решили проверить гипотезу: можно ли использовать только эту естественную
паузу для короткого рекламного показа, не превращая редактор в баннерную панель
и не получая доступ к содержимому работы. Так появилось расширение Kodpauza для
VS Code, Cursor и VSCodium.

В статье разберём не маркетинг, а технические ограничения, из-за которых
простая на первый взгляд задача потребовала lifecycle-событий, локального
bridge, fail-closed патчей, доказательства видимости и идемпотентного
финансового учёта.

## Что именно считается паузой

Нельзя считать паузой просто открытое окно редактора или запущенное расширение.
Рекламная строка должна существовать только пока Codex или Claude Code
действительно выполняет запрос пользователя.

Для этого интеграция отслеживает два события:

1. AI начал выполнять задачу.
2. AI завершил выполнение или был остановлен.

Codex предоставляет lifecycle hooks. Локальный обработчик получает событие и
передаёт bridge только его тип и контекст рабочей сессии. Для Claude Code
используется отдельный адаптер с тем же минимальным контрактом.

Текст запроса, ответ модели, исходный код и содержимое терминала для определения
состояния не нужны.

## Почему нужен локальный bridge

Hook и UI редактора живут в разных процессах. Поэтому между ними работает
локальный HTTP bridge, доступный только через loopback-интерфейс.

У него несколько задач:

- принять событие начала или завершения;
- проверить подпись локального сообщения;
- связать событие с активным окном;
- включить или убрать рекламную строку;
- пережить перезапуск окна и конфликт временного порта.

Bridge не отправляет в рекламный API путь рабочей папки. На сервер уходят только
идентификаторы рекламного события, версия поддерживаемого инструмента и
доказательство видимости.

## Патчить интерфейс можно только с доказанной совместимостью

Codex и Claude Code обновляются независимо от Kodpauza. Если безусловно менять
их собранный UI после каждого обновления, одна переставленная функция может
сломать расширение или сам интерфейс агента.

Поэтому установка патча работает по принципу fail closed:

1. Для известных сборок проверяются контрольные суммы и структурные якоря.
2. Для новой сборки допускается только структурное совпадение всех независимых
   признаков.
3. Перед изменением создаётся резервная копия.
4. Результат повторно разбирается синтаксическим анализатором.
5. При неоднозначности патч не применяется, реклама отключается, а оригинальный
   AI-интерфейс продолжает работать.

Повторная установка идемпотентна. Частичная установка обнаруживается и
исправляется, а удаление интеграции восстанавливает исходные файлы.

## Пять секунд — это не просто таймер

Запустить `setTimeout` на пять секунд недостаточно. Пользователь может свернуть
окно, переключиться на другой редактор, закрыть блок рассуждений или перекрыть
рекламную строку другим элементом.

Подтверждённый показ требует одновременно выполнить несколько условий:

- окно редактора находится в фокусе;
- рекламная строка непрерывно видна не менее пяти секунд;
- не менее 80% её площади находится внутри viewport;
- элемент не скрыт стилями и не свёрнут вместе с родительским блоком;
- реклама не перекрыта другим интерфейсным элементом;
- это объявление ещё не было оплачено в рамках данной выдачи.

Если любое условие перестаёт выполняться, незавершённый интервал сбрасывается.
При нескольких открытых окнах учитывается только окно в фокусе.

## Как не списать деньги дважды

Каждая серверная выдача получает ограниченный срок жизни и уникальный
идентификатор события. Клиент подписывает подтверждение ключом устройства,
который хранится в VS Code SecretStorage.

Если сеть временно недоступна, событие остаётся в локальной очереди и
отправляется повторно с тем же `eventId`. Сервер обрабатывает повтор
идемпотентно: повторная доставка не создаёт второе списание и второе
начисление.

Сначала событие проходит антифрод-проверку. Подозрительный показ может остаться
в технической статистике, но рекламодатель за него не платит и разработчик не
получает вознаграждение.

Для чистого показа рекламодатель оплачивает фактическую стоимость, а 50%
начисляется разработчику. Дробные копейки не теряются: остаток переносится в
следующее начисление.

## Клик и маркировка рекламы

ERID хранится не в расширении и не в глобальной переменной, а в конкретной
кампании. API возвращает его отдельным полем и одновременно добавляет в
кликабельный URL.

Если ссылка уже содержит UTM-параметры или fragment, они сохраняются. Старый
`erid` заменяется, а повторная нормализация не создаёт дубль. Клиент перед
открытием дополнительно разрешает только HTTP/HTTPS-ссылки.

Так старые версии расширения получают уже маркированный адрес от API, а новые
имеют дополнительную клиентскую страховку.

## Что намеренно не делали

Мы отказались от нескольких очевидных способов увеличить количество показов:

- не показываем рекламу постоянно в отдельной панели;
- не запускаем показ просто по открытому редактору;
- не читаем промпты, ответы, код или команды терминала;
- не просим пользователя искусственно создавать ожидания;
- не засчитываем скрытый или потерявший фокус интерфейс;
- не применяем патч, если совместимость новой сборки не доказана.

Эти ограничения уменьшают рекламный инвентарь, но делают единицу показа
понятной: это реальная видимость во время обычной работы с AI.
